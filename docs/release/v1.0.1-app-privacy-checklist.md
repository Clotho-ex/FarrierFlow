### PostHog provider-owned context

The pinned SDK source shows these properties on custom events:

| Data | Behavior and classification note |
| --- | --- |
| Anonymous distinct/device ID | Random UUIDv7 generated and persisted per installation; used across sessions for anonymous funnels and retention. FarrierFlow never reads or links it. |
| Session ID | Random UUIDv7 held in memory; a session is created for foreground event activity, rotates after 30 minutes of inactivity, and has a 24-hour maximum. This does not emit FarrierFlow's deferred `app_session_started`. |
| Event UUID and timestamp | UUIDv7 plus UTC timestamp used for event identity and ordering. |
| App metadata | App name, bundle identifier, app version, and build. |
| SDK metadata | PostHog library name and version. |
| Device metadata | Apple manufacturer, hardware model, generic device type/name, screen width and height, Simulator, iOS-on-Mac, and Catalyst flags. On iPhone, the generic model is used rather than the user-assigned device name. |
| OS metadata | OS name and version. |
| Regional metadata | Current language code and time-zone identifier. |
| Network metadata | Boolean Wi-Fi and cellular reachability; no carrier name in the pinned source. |
| Distribution metadata | TestFlight and sideloaded flags. |
| Privacy controls | `$is_identified=false`, `$process_person_profile=false`, and FarrierFlow's fixed `$geoip_disable=true`. |
| Source IP | The request necessarily reaches ingestion from an IP address. The owner reports that the project discards client IP data, and every event disables GeoIP enrichment. Confirm both settings again before release. |

The SDK sends to the tracked United States ingestion host
`https://us.i.posthog.com` and stores a file-backed event queue for offline
delivery, with a default maximum of 1,000 events, flush threshold of 20, batch
maximum of 50, and a 30-second flush interval. FarrierFlow adds no queue, event
store, retry system, or identifier of its own.

The provider is explicitly configured with lifecycle, screen, element,
swizzling, push, session replay, surveys, feature-flag preload/events, person
profiles/defaults, rage-clicks, logs, and error/crash autocapture disabled.
FarrierFlow never calls `identify`, `alias`, `group`, person-property,
super-property, manual-screen, replay, survey, flag, error, or log APIs. PostHog
3.74.0 still makes its unavoidable token-scoped remote-configuration setup
request, but FarrierFlow does not use that response for product behavior.

No FarrierFlow business-record contents enter PostHog. The typed boundary
cannot accept names, contact details, addresses, notes, photographs, invoice or
payment contents, values, record IDs, RevenueCat IDs, or arbitrary strings.

## RevenueCat and Apple Ads data-flow inventory

- FarrierFlow configures RevenueCat without a custom App User ID. RevenueCat
  generates a random ID prefixed with `$RCAnonymousID:` and caches it on the
  device. Reinstalling generates a new anonymous ID; restore behavior may
  associate purchase history according to RevenueCat's project settings.
- RevenueCat receives App Store receipt and transaction information,
  subscription product and purchase history, entitlement status, renewals,
  cancellations, and restores. FarrierFlow receives only the subscription
  snapshot needed to decide whether Pro access is active.
- Purchase history is used for entitlement/app functionality and RevenueCat
  customer history and analytics. Apple—not FarrierFlow—handles payment-card
  and bank details.
- After RevenueCat configuration, FarrierFlow enables Standard AdServices
  attribution with
  `purchases.attribution.enableAdServicesAttributionTokenCollection()`.
  RevenueCat fetches the Apple token asynchronously, submits it in the
  background, and caches delivery bookkeeping so it is not posted repeatedly.
  FarrierFlow does not manually fetch, decode, parse, or persist the token.
- When Apple supplies it, RevenueCat can store attribution source, campaign,
  ad group, keyword, and claim type alongside the anonymous subscription
  customer for Charts and subscription/revenue analysis.
- FarrierFlow does not import AppTrackingTransparency or AdSupport, request
  ATT, access IDFA, call `collectDeviceIdentifiers()`, fingerprint a device,
  create an install ID, or provide customer PII or custom subscriber
  attributes.
- RevenueCat and PostHog identities are not linked. No attribution token,
  campaign, ad-group, keyword, or claim value enters PostHog,
  `AnalyticsEvent`, or a FarrierFlow business record.

## Supporting questionnaire notes

### Purchases — Purchase History

| Question | Prepared answer | Evidence and reasoning |
| --- | --- | --- |
| Collected? | **Yes** | RevenueCat receives and retains App Store receipt/subscription history; its archive manifest declares Purchase History. |
| Purpose | **App Functionality and Analytics** | Entitlement/receipt validation provides app functionality; RevenueCat customer history and Charts provide analytics. RevenueCat's current App Privacy guidance explicitly recommends both. |
| Linked to identity? | **No** | FarrierFlow supplies no custom ID or PII. RevenueCat uses anonymous App User IDs, and its packaged manifest declares Purchase History unlinked. |
| Used for tracking? | **No** | No IDFA, ATT, cross-provider identity bridge, data broker, or cross-app targeting. The Apple Ads integration collects Apple attribution into RevenueCat rather than forwarding FarrierFlow users or purchase events to PostHog. |

Purchase History's approved purposes are App Functionality and Analytics. The
owner assigns Developer's Advertising or Marketing to **Advertising Data**, not
Purchase History.
